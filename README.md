# pair-wise-yf-52 戏剧排练台词版本与舞台提示管控

## 源提示词摘要
联排期间编剧持续交修订稿，舞台监督在排练版本上逐条标记采纳/退回；演员可离线记录疑问。
系统需保证：编剧新稿合并不冲掉已有结论、双方都改过的条目进待裁决、离线或基线漂移导致合并失败的改动留在待处理队列可继续处理；
演员疑问锚定具体台词与所看版本，版本一变即过期需重新确认，与新退回结论冲突的优先展示。

## 技术栈
Angular + TypeScript + Angular Material + NgRx + Angular Router + RxJS + Angular CDK + Transloco。

## 合并规则（编剧新稿 → 排练版本，三方合并）
- 稿件记录基线版本 ID 与修订号（revision）；基线版本不符或修订号已推进：**整体合并失败，一条改动都不落地**，进入「待处理」队列。
- 稿中未改过的台词：**保留舞台监督原结论**（已采纳/已退回原样保留）。
- 舞台监督尚未下结论（待确认）而编剧改了文：直接落地新文，结论仍待确认。
- 舞台监督已采纳/退回、编剧又改了：原文与原结论不动，挂入「待裁决」，可选择维持原结论、采纳编剧稿或采用混合文本——**退回不会被新稿冲掉**。
- 全新条目以待确认加入；每次内容/结论推进时版本 revision 自增。

## 演员疑问
- 每条疑问锚定「记下时的版本 + 修订号 + 那句台词」。
- 离线记录先进待同步队列，恢复网络后逐条标记已同步并挂回原句（离线交稿同样先进待处理，恢复网络自动重试）。
- 版本修订号变化 → 「已过期」，需按当前版本重新确认；锚定台词被移除 → 提示锚点失效。
- 台词当前结论为退回时标记「与退回结论冲突」；冲突疑问排最前，其次过期，其余按时间排序。

## 待处理队列
- 合并失败（离线、基线漂移）的改动持久保留在待处理中，重开页面不丢失；支持重试合并、变基到当前版本后重试、丢弃。
- 待裁决、疑问、采纳/退回结论均经 localStorage 持久化，旧数据结构自动迁移补齐 revision 等新字段。
